## 2024-05-20 - PostgREST Filter Injection Vulnerability in Supabase Queries
**Vulnerability:** User input was passed directly into a Supabase `.or()` string expression without escaping or quoting (`query.or(\`name.ilike.\${like}\`)`). If the input contained PostgREST structural characters (like `"`, `,`, `(`, or `)`), it would alter the query structure, potentially allowing attackers to run arbitrary filters or bypass access checks.
**Learning:** Supabase's JavaScript SDK does not automatically parameterize or escape strings passed directly to `.or()` and similar raw filter methods when using template literals. This is a common pitfall because developers assume ORM-like tools always handle parameterization.
**Prevention:** Always escape user input before passing it into raw PostgREST expressions. For string fields, replace internal double quotes (`replace(/"/g, '""')`) and wrap the entire interpolated string in double quotes (e.g. `query.or(\`name.ilike."\${safeTerm}"\`)`).
